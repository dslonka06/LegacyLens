Architecture Summary

Architecture Summary is determined entirely without AI. The engine checks folder and file names against known layer keywords — things like "controllers", "services", "repositories", "components" — and counts hub nodes and framework signals. From this it recognises patterns like Layered, MVC, or Event-driven.

Each detected pattern gets a confidence score based on how many expected structural indicators were actually found. The top matches are shown, with the strongest one displayed as the primary architecture.

Layer Diagram

Layer Diagram is generated after the architecture analysis completes. Each file is placed into one of four layers — Presentation, Business Logic, Data Access, or External — based on its name and file path matching known layer keywords.

To keep the diagram readable, up to 4 representative files per layer are chosen (the most-referenced ones), and up to 12 cross-layer connections are drawn. No AI is involved — it renders directly from the dependency graph using a top-down layout.

Structural Analysis

Coupling describes how concentrated your dependencies are. It's based on the proportion of files that act as hubs (5+ other files depending on them). Critical means more than 1 in 5 files is a hub; High means more than 1 in 8; Moderate means more than 1 in 16; Low means the codebase is reasonably spread out.

Hub Nodes is simply the count of files that 5 or more other files import. A high number means many parts of the codebase share a small set of central files — changes to those files ripple widely.

Circular Deps counts dependency cycles — cases where file A depends on B which eventually depends back on A. These prevent clean isolation and can cause subtle loading or initialisation issues.

Hub Nodes are files that at least 5 other files depend on. They're ranked by their total number of connections — both how many files call them (inbound) and how many they call (outbound).

These are the architectural hotspots of the codebase. A change to a hub file can cascade to every file that imports it, so they carry higher risk during refactoring and deserve extra attention when reviewing changes.
