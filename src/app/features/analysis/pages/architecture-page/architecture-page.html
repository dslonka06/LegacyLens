Dependency Layer Diagram

Dependency Layer Diagram groups files into four architectural layers — Presentation, Business Logic, Data Access, and External — based on file name and path patterns. Edges show which layers depend on which, giving a structural overview of how data and control flow through the codebase.

Up to 4 representative files per layer are shown (the most-referenced ones) and up to 12 cross-layer edges are drawn to keep the diagram readable. No AI is involved — it renders directly from the dependency graph.

File Roles

File Roles classifies each file by its structural role in the architecture: controller (external entry points), service (business logic), repository (data access), http-client (external API bridges), state-store (shared reactive state), and component (UI layer).

Classification is heuristic — it combines content signals (decorators, imports, method patterns) with file naming. Files that could not be classified are excluded. Each description explains what the file does in context.

Hub Nodes are files that at least 5 other files depend on. They're ranked by their total number of connections — both how many files call them (inbound) and how many they call (outbound).

These are the architectural hotspots of the codebase. A change to a hub file can cascade to every file that imports it, so they carry higher risk during refactoring and deserve extra attention when reviewing changes.
