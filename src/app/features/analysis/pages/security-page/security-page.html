Security Findings {{ findings.length }}

Security Findings are produced in two stages. First, all files are scanned using regex patterns across 8 security domains — Secrets, SQL Injection, Authentication, Authorisation, Input Validation, Data Access, Logging, and Error Handling. This produces raw evidence: specific code matches that look potentially risky.

That raw evidence is then sent to the AI, which reviews it and decides which matches represent genuine issues. The AI produces confirmed findings with a severity level, category, the specific file and line, an explanation of what the issue is, why it matters, and how to fix it. Only AI-confirmed findings appear here — pattern matches that the AI dismisses as false positives are discarded.

Security Verification

Security Verification is entirely deterministic — no AI is involved. Each of the 8 security domains is assessed independently based on what patterns were and weren't found in the scan.

Pass means the scan found protective patterns in place — things like auth middleware, parameterised queries, or structured logging. Warn means the signals were mixed or incomplete. Fail means the scan found risky patterns (e.g. string-built SQL queries, empty catch blocks, hardcoded secrets) without corresponding safeguards.

Expand any domain check to see the specific code evidence that determined its result.
