Code Health

Complexity measures how tangled the codebase's internal wiring is. For multi-file targets, it looks at the ratio of import relationships to total files — a low ratio means modules are mostly independent, a high ratio means everything is heavily cross-connected. For a single file, it uses raw line count as a proxy. Low is under 30 non-blank lines (or ratio ≤ 2), High is over 75 lines (or ratio > 4).

Maintainability reflects how safely you can change things without breaking something else. It combines file count with coupling density — a small, loosely connected codebase scores High, a large and tightly coupled one scores Low. For single files it pulls from the file type's known maintenance profile.

Risk Level is the overall health verdict — Healthy, Fair, Needs Attention, or Critical — derived by combining the Complexity and Maintainability scores into a single tier.

Business Purpose

Business Purpose is inferred from the structure of the codebase without any AI. It looks at which top-level folders are present — for example, finding api, ui, and data folders together suggests a full-stack system; services and repositories together suggest a backend service; components and pages alone suggest a frontend application.

For a single file, the purpose is drawn from a built-in profile for that file's type — an Angular Component always has a UI rendering purpose, a Repository always has a data access purpose, and so on.

The narrative text below (when present) is written by the AI, using all the derived structural context — criticality, capabilities, architecture — to explain the purpose in plain language.
